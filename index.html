CAREER OS · ARCHITECTURE DOSSIER

Prayan 🧭 — Career Operating System

DAG Roadmap Engine · Socratic AI Mentor · Adaptive Study Calendar

Problem Statement

Students consume fragmented tutorials with no dependency sequencing, leading to knowledge gaps and failed interviews. Prayan (Sanskrit: "Journey / Onward March") solves this by representing every career curriculum as a Directed Acyclic Graph (DAG) — each node unlocks only after its prerequisites are verified by quiz scores.

Core Architecture Pillars

LAYER 1
NLP Goal Resolver + DAG Engine

Fuzzy-match + token-overlap NLP engine maps natural language goals to 1 of 18 career tracks with a confidence score. Kahn's algorithm enforces topological ordering; nodes unlock only when all prerequisite quiz gates pass at ≥80%.

LAYER 2
Adaptive Study Calendar + Progress Engine

Distributes remaining curriculum across future dates based on weekly pace (5–30+ hrs). Re-balances dynamically on pace change. Mathematical readiness formula: 0.40×Nodes + 0.25×Quizzes + 0.25×Projects + 0.10×Consistency.

LAYER 3
Socratic AI Mentor + Multi-Provider Fallback

Groq (llama-3.3-70b) → Gemini (gemini-1.5-flash) → Firebase Cloud Function → local rule engine. Provides guided Socratic hints rather than direct answers to preserve deep learning. In-browser multi-language code sandboxes simulate real execution.

Engineering Challenges

Challenge 1
Topology-Aware Node Unlocking

Implemented Kahn's topological sort on the full curriculum DAG to determine tier ordering. Node unlock events trigger cascading prerequisite re-evaluation using a BFS propagation queue — ensuring no race conditions in async Firebase writes.

Challenge 2
Multi-Provider AI Fallback Chain

Groq primary → Gemini secondary → Firebase Cloud Function → local Socratic rule engine. Each provider has a 3-second timeout with graceful degradation, ensuring 100% uptime for the mentor experience even during API outages.

Challenge 3
Offline-First Firebase Sync

All progress, quiz scores, and calendar data are persisted to localStorage first, then batch-synced to Firestore on reconnect. Conflict resolution favors the most recent timestamp, preventing data loss during network interruptions.

ARCHITECTURE DOSSIER

Gyan 🧠 — AI Repository Intelligence Platform

Deterministic Codebase Analysis · Evidence-Grounded AI Reasoning

Problem Statement

Understanding legacy or unfamiliar codebases is a critical bottleneck. Generic LLMs hallucinate file paths, miss dependency couplings, and fail to understand execution flows. Gyan solves this by pairing deterministic AST analysis with Gemini 1.5 Flash — forcing strictly verifiable file + line-number citations.

3-Tier Architecture

TIER 1
Deterministic Static Scanning Engine

Recursively parses ASTs to extract classes, functions, imports & exports. Cross-references 90+ framework rules across 9 dev categories. Reverse-engineers REST routes (FastAPI, Express, Django, Spring Boot) and ORM schemas (SQLAlchemy, Prisma, TypeORM).

TIER 2
Context-Grounded RAG Retrieval Brain

Language-aware 50-line overlapping code chunks. In-memory TF-IDF vector index with cosine similarity for sub-second zero-dependency retrieval. Powers Copilot via Gemini 1.5 Flash with strict system prompts enforcing exact file and line-number citations.

TIER 3
Interactive 22-Module Developer Workspace

Hardware-accelerated interactive canvas visualizing 6-tier architecture (Client, API Gateway, Services, Persistence, Cache, Infrastructure). Generates live ER diagrams, 5-tier blast-radius analysis, AI Code Staging Cockpit with diff previews & approval workflows.

Key Engineering Challenges

Challenge 1
Zero-Hallucination AI Citations

Solved LLM inaccuracies by pairing vector search with deterministic AST symbol tables, forcing the model to strictly cite verified file paths and line ranges.

Challenge 2
Multi-Framework Static Parsing

Unified regex and AST traversal heuristics detect routes, models, and dependencies across Python, JavaScript, TypeScript, Go, and Java — without executing untrusted code.

Challenge 3
High-Performance In-Memory Retrieval

TF-IDF indexing with sparse vector cosine similarity removes the overhead of external hosted vector databases — scaling to enterprise-size repositories.
